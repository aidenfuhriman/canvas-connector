# Canvas Connector — Design Spec

Date: 2026-09-06

## Goal

Give Claude Code interactive access to the user's Canvas LMS account (courses,
assignments, grades, discussions, calendar), including the ability to submit
assignment work and post discussion replies/comments on the user's behalf.
Also deliver proactive daily email reminders of upcoming/unsubmitted work.

## Non-goals

- No instructor/admin tooling (course creation, enrollment management,
  grading other students, rubric authoring). This is a student-facing
  connector only.
- No support for Claude Desktop or claude.ai (web) in this iteration — Claude
  Code (CLI) only, per user request.
- Not a general Canvas API client library — only the operations needed for
  the use cases below.

## Background

Evaluated two existing open-source Canvas MCP servers before deciding to
build custom:

- `vishalsachdev/canvas-mcp` — actively maintained (pushed same day as
  evaluation), 230★, clean MIT license, 100+ tools. Missing: no tool for a
  student to submit their own assignment work, no calendar tool.
- `DMontgomery40/mcp-canvas-lms` — on paper covers submit/post/calendar via
  `canvas_submit_assignment`, `canvas_post_to_discussion`,
  `canvas_list_calendar_events`. But stale (no commits in 3+ months at time
  of evaluation), no LICENSE file (open issue titled "License file needed"),
  and an open bug report ("Unknown tool: canvas_list_modules").

Neither cleanly covers all four required capabilities (read, submit,
post/comment, calendar) with acceptable maintenance/license posture, so this
spec defines a small custom server scoped exactly to what's needed.

## Architecture

Two independent components sharing one Canvas API client module, in a single
repo at `~/projects/canvas-connector`:

```
canvas-connector/
  src/
    canvasClient.ts       # shared: auth, pagination, error handling
    mcp/
      server.ts           # canvas-mcp: MCP stdio server, tool definitions
      tools/*.ts
    reminder/
      check.ts            # canvas-reminder: standalone script, run on a cron
  docs/superpowers/specs/
  .env.example
  package.json
  tsconfig.json
```

### 1. `canvas-mcp` (local MCP server)

TypeScript, `@modelcontextprotocol/sdk`, stdio transport. Registered with
Claude Code via `claude mcp add`. Runs only on the user's machine, only
while invoked from a Claude Code session.

### 2. `canvas-reminder` (scheduled routine)

A standalone script (not going through the MCP tool-call layer) that:
1. Calls the Canvas REST API directly for assignments due in the next N days
   across the user's active courses.
2. Filters to those without a submitted status.
3. Sends a summary email via the user's Gmail connector.

Runs on a schedule via the `schedule` skill (cloud-scheduled agent), since a
cron job tied to the user's laptop being on is not reliable for daily
reminders. Because scheduled cloud agents cannot reach a stdio process
running only on the user's laptop, this script talks to the Canvas API
directly rather than through `canvas-mcp`. It reuses `canvasClient.ts` for
the actual HTTP/auth logic to avoid duplicating that code.

**Open question, resolved during implementation:** where the scheduled
routine's environment gets `CANVAS_API_TOKEN` / `CANVAS_DOMAIN` from (the
`schedule` skill's env/secret mechanism — TBD at build time, not blocking
the rest of the design).

## Auth / config

- `CANVAS_API_TOKEN` — a Canvas personal access token, generated by the user
  from Canvas → Account → Settings → New Access Token.
- `CANVAS_DOMAIN` — the user's institution's Canvas domain (e.g.
  `school.instructure.com`).

Stored in a local `.env` (gitignored) for `canvas-mcp`. The reminder
routine's copy of these values lives wherever the `schedule` skill's
scheduled-agent config puts secrets.

## Tools exposed by `canvas-mcp`

Read:
- `list_courses` — active courses for the current user.
- `list_assignments(course_id)` — assignments with due date + submission
  status.
- `get_assignment(course_id, assignment_id)`
- `list_grades(course_id?)` — current grades, optionally scoped to a course.
- `list_discussion_topics(course_id)`
- `list_calendar_events(start, end)`

Write (all require `confirm: true`, see Safety below):
- `submit_assignment(course_id, assignment_id, { text? | url? | file_path? }, confirm)`
- `post_discussion_reply(course_id, topic_id, message, confirm)`
- `add_submission_comment(course_id, assignment_id, comment, confirm)`

## Safety

`submit_assignment`, `post_discussion_reply`, and `add_submission_comment`
all require an explicit `confirm: true` parameter. Without it, the tool
returns a preview of what it would do instead of performing the action. This
guards against submitting real coursework or posting a comment from a
misread instruction — these are actions with real academic consequences and
limited undo.

## Data flow

**Interactive:** Claude Code → `canvas-mcp` tool call → Canvas REST API →
response → Claude formats it for the user.

**Reminder:** cron trigger (via `schedule` skill) → `canvas-reminder`
script → Canvas REST API (assignments + submissions) → filter to
due-soon/unsubmitted → send via Gmail connector → email in the user's inbox.

## Error handling

- Canvas API errors (401 bad/expired token, 403 permission, 404 not found,
  429 rate limit) are caught in `canvasClient.ts` and re-thrown as clear,
  human-readable tool errors — not raw HTTP stack traces.
- If the reminder script's Canvas call fails, no email is sent that run
  (fail quiet, not fail loud) — avoids spamming the user with error emails
  for a job they didn't directly invoke.

## Testing plan

- Read tools (`list_courses`, `list_assignments`, `list_grades`,
  `list_discussion_topics`, `list_calendar_events`) verified against the
  user's real Canvas account.
- Write tools (`submit_assignment`, `post_discussion_reply`,
  `add_submission_comment`) verified against a low-stakes real
  assignment/discussion (or a sandbox course, if the user has one) before
  being trusted for real coursework — including verifying the `confirm`
  guard actually blocks unconfirmed calls.
- Reminder script tested with a manually-triggered run before it's put on a
  schedule, to confirm the email content and filtering logic look right.

## Defaults

- Reminder frequency: daily.
- Lookahead window: assignments due in the next 3 days.
- Delivery: email to the user's connected Gmail account.
- Repo location: `~/projects/canvas-connector`.
- Language: TypeScript.
